# freegma 설계

> 상태: 초안(개정 6 — 디자인 시스템, `freegma/` 디렉토리·배포 제외, Claude 가져오기, ✦ AI 채팅 탭, 브랜치 메뉴, 화면·도메인↔코드 2026-11-21, 반영표 §15) | 작성: 2026-11-19 | 참고: `docs/ref/design-ref.md`(cl-app 설계 문서 형식 차용, 로컬 전용 — git 제외), `docs/design-system.md`(디자인 시스템 상세)
> 한 줄 요약: 로컬에 설치해 쓰는 UI/UX 디자인·프로토타이핑 툴(Electron). 디자인은 사람이 읽을 수 있는 텍스트 파일로 저장하고 [커밋] 버튼으로 Git에 남긴다. 로그인·서버 없이, AI가 MCP로 디자인을 읽고 고치며, 개발자 모드는 프로젝트의 개발 스펙에 맞는 코드를 만든다.

## 0. 원칙 (우선순위 순서)
1. **파일이 원본.** 디자인의 유일한 원본은 저장소 안의 텍스트 파일이다. 앱·MCP·AI 모두 이 파일을 읽고 쓴다. 서버·계정·로그인·클라우드 저장소는 없다.
2. **Git 친화.** 작은 수정은 작은 diff로 남아야 한다(속성 하나 바꾸면 파일 하나, 몇 줄). 버전 기록·브랜치·인증은 Git과 이 PC의 git 설정에 맡기고 앱이 따로 만들지 않는다.
3. **AI가 1급 사용자.** 사람이 화면에서 할 수 있는 일은 MCP로도 할 수 있어야 한다. 사람이 고른 선택 영역을 AI가 바로 읽을 수 있어야 한다(«이거 고쳐줘»).
4. **코드는 스펙에 맞게.** 개발자 모드는 CSS 조각이 아니라, 그 프로젝트가 쓰는 프레임워크·스타일 방식·컴포넌트·토큰 이름으로 코드를 낸다.
5. **반응성.** 캔버스 이동·확대·선택은 끊기지 않아야 한다. 기능을 늘리기 전에 §9 목표부터 지킨다.
6. **앱 안에 AI는 없다 — AI는 사용자의 Claude Code, 통로는 MCP 하나.** 앱은 AI 모델·API 키를 갖지 않는다. 앱 안 ✦ AI 채팅 탭(§2-6)과 «저장소에서 가져오기»는 사용자 PC의 Claude Code를 실행하는 화면일 뿐이고, 그 Claude도 터미널의 Claude Code와 **똑같은 freegma MCP 도구·검사 규칙**을 거친다. 이때 허용 도구는 freegma MCP와 저장소 읽기뿐이다.
7. **디자인 시스템이 먼저.** 프로젝트는 디자인 시스템(토큰·글자 스타일·컴포넌트·사용 규칙)과 함께 만들어지고, 페이지는 그 위에서 만든다. 사람이 보는 시스템 화면과 AI가 읽는 내용은 같은 파일에서 나온다(`docs/design-system.md`).

## 1. 쓰는 흐름 (혼자 디자인·개발)
```
① 사람: 앱에서 서비스 저장소를 연다 → freegma/ 폴더가 없으면 만든다(웹/모바일 앱 + 개발 스펙 + 디자인 시스템)
   └ 디자인 시스템: 브랜드 색·서체만 고르면 토큰·글자 스타일·기본 컴포넌트가 생긴다(또는 저장소 테마에서 가져오기)
② 사람: 왼쪽 «디자인 시스템»에서 확인·손보기 → 대략 그리거나, AI에게 «상품 상세 화면 만들어줘»
③ AI(Claude Code 등): MCP get_design_system으로 시스템(토큰 용도·컴포넌트 규칙)을 먼저 읽고, 그 토큰·컴포넌트로만 프레임을 만든다 → 앱 화면에 바로 보임
④ 사람: 캔버스에서 손보고, 고칠 곳을 선택한 뒤 AI에게 «이 카드 간격 토큰으로 맞춰줘»
⑤ AI: MCP render_image로 결과를 눈으로 확인하며 반복
⑥ 사람: [커밋] 버튼 → 자동으로 채워진 메시지 확인 → freegma/ 변경이 커밋됨
⑦ 사람/AI: 개발자 모드 → 스펙(React+Tailwind 등)에 맞는 코드를 앱 코드에 반영 → 코드는 터미널·AI가 커밋
```
- 디자인은 **서비스 코드와 같은 저장소(같은 GitHub 저장소)의 `freegma/` 디렉토리**에 둔다. 디자인 커밋과 코드 커밋이 같은 브랜치·같은 PR에 들어가고, AI가 디자인과 코드를 한 작업 공간에서 본다.
- 단, **배포에는 포함되지 않게** 프로젝트를 만들 때 배포 제외 설정을 한다(§2-1-2). 디자인 히스토리는 `design(...)` 접두어와 경로로 걸러 볼 수 있다(코드만: `git log -- . ':!freegma'`, 디자인만: `git log -- freegma/`).
- 디자인 저장소를 따로 두는 안은 검토 후 버렸다: 히스토리는 완전히 나뉘지만, 코드와 디자인을 같은 PR로 묶을 수 없고 AI 작업 공간이 둘로 갈린다. 혼자·작은 팀 개발에는 같은 저장소 + 배포 제외가 맞다.
- 앱의 [커밋]은 `freegma/`만 커밋한다. 코드 커밋은 앱이 하지 않는다(§5-1).

## 2. 화면 구성

> 클릭해 볼 수 있는 목업: `docs/mockup/index.html` (브라우저로 열기). 이 절의 그림을 그대로 옮긴 것이다.

### 2-1. 시작 화면
```
┌──────────────────────────────────────────────────────────┐
│  freegma                                                 │
│                                                          │
│  [ 폴더 열기 ]   [ 새 디자인 프로젝트 ]                     │
│                                                          │
│  최근 프로젝트                                             │
│   my-shop        ~/work/my-shop       main   어제         │
│   blog           ~/personal/blog      dev    3일 전        │
│                                                          │
│  ⚠ git 저장소가 아닌 폴더입니다. [git init] [그냥 열기]       │
└──────────────────────────────────────────────────────────┘
```
- **폴더 열기**: 서비스 저장소 루트를 고른다. `freegma/project.json`이 있으면 바로 열고, 없으면 «이 저장소에 디자인 프로젝트 만들기»를 제안한다.
- **새 디자인 프로젝트**: 아래 «프로젝트 만들기» 창(§2-1-1)을 거쳐 `freegma/` 뼈대(설정·스펙 프로필·**디자인 시스템**)를 만든다.
- **git 저장소가 아닐 때**: [git init]을 제안한다. «그냥 열기»도 되지만 [커밋] 버튼이 꺼진다.
- 로그인·계정 화면은 없다. 앱을 켜면 바로 이 화면이다.
- 프로젝트 하나 = 창 하나. 여러 프로젝트는 여러 창으로.

#### 2-1-1. 프로젝트 만들기 (플랫폼 선택)
```
┌ 새 디자인 프로젝트 ─────────────────────────────────┐
│ 이름        [ my-shop                       ]      │
│ 서비스 저장소 [ ~/work/my-shop            ] [찾기]    │
│   → 이 저장소 안 freegma/ 에 저장                     │
│                                                   │
│ 무엇을 만드나요?                                     │
│  ( ● ) 웹            ( ○ ) 모바일 앱                 │
│                                                   │
│ 개발 스펙                                           │
│  [ React + Tailwind CSS          ▾ ]  ← 플랫폼별 목록 │
│  ⓘ 저장소에서 package.json 감지: React 19, Tailwind 4 │
│                                                   │
│ 디자인 시스템                                        │
│  [● 기본 템플릿]  [ 저장소에서 가져오기 ✦ ]            │
│  (템플릿일 때) 브랜드 색 [■ #2563EB] 서체 [Pretendard▾]│
│  (가져오기일 때) ✓ Claude 연결됨 · 분석 범위 [ ./ ]     │
│                                                   │
│                    [취소]  [만들기 → 배포 제외 설정]   │
└───────────────────────────────────────────────────┘
```
- **플랫폼을 먼저 고르고, 그 플랫폼의 개발 스펙을 고른다.** 이 선택이 `freegma/spec.json`(§7)이 되고, 개발 모드의 코드 생성 대상이 된다.
- **디자인 시스템을 함께 만든다.** 시작 방식은 두 가지이고, 방식마다 입력이 다르다(`docs/design-system.md` §2).
  - **기본 템플릿**: 브랜드 대표 색 하나와 서체만 받아 기초값(brand.50~900·회색·상태 색), 의미 토큰, 글자 스타일 5개, 간격·모서리·그림자 단계, 기본 컴포넌트(Button · Input · Badge · Card)를 만든다.
  - **저장소에서 가져오기 ✦**: **Claude Code가 연결돼 있을 때만** 고를 수 있다. Claude가 저장소의 디자인 방식을 분석해 `freegma/system/`에 freegma 형식으로 **다시 만들고**, 사람은 «가져오기 초안»(출처·확신도)에서 확인·확정한다. 저장소 테마를 규칙으로 옮기지 않는 이유: 저장소 방식이 freegma 형식과 맞지 않는 경우가 많다.
  - 빈 시스템은 없다(AI가 원시값을 지어내게 되므로).
- 순서: 이 창 → **배포 제외 설정**(§2-1-2) → (가져오기면) Claude 분석 → 가져오기 초안 → 편집 화면(디자인 시스템 화면, §2-5).
- 기존 저장소를 열 때는 파일을 보고 미리 골라 둔다(`package.json`의 react/vue/react-native, `pubspec.yaml`이면 Flutter, `.xcodeproj`면 iOS 등). 사람은 확인만 한다.
- **플랫폼이 바꾸는 것**(코드 생성만이 아니라 디자인 기본값도)

| | 웹 | 모바일 앱 |
|---|---|---|
| 기본 프레임 크기 | 데스크톱 1440 · 태블릿 768 · 모바일 390 | iPhone 393×852 · Android 412×915 |
| 단위 표시 | px | pt(iOS) / dp(Android), 저장은 같은 숫자 |
| 디자인 시스템 기본값 | 글자 14·16·20·28·40px, 간격 4px 단계, 버튼 최소 40px | 글자 13·15·17·22·28pt, 간격 4pt 단계, 안전 영역 토큰, 버튼 최소 44pt |
| 프로토타입 전환 | 페이지 이동·오버레이 | 밀어 넣기(push)·모달·탭 전환, 뒤로 가기 제스처 |
| 미리보기 창 | 브라우저 창 크기 | 기기 틀 안에서 |
| 개발 스펙 목록 | React+Tailwind(1차), Vue, React+CSS Modules … | 1차 하나(§16-4), 이후 Flutter·SwiftUI·Jetpack Compose |

- 플랫폼은 나중에 설정에서 바꿀 수 있다. 바꾸면 기존 프레임은 그대로 두고 코드 생성 대상·기본값만 바뀐다.
- 웹과 모바일 앱을 한 프로젝트에서 같이 하는 경우(반응형 웹 + 앱)는 2차. 1차는 프로젝트 하나에 플랫폼 하나.

#### 2-1-2. 배포에서 freegma/ 제외
```
┌ 배포에서 freegma/ 제외 ─────────────────────────────────────┐
│ ☑ .dockerignore               + freegma/      (Dockerfile 감지) │
│ ☑ .github/workflows/deploy.yml  paths-ignore: ['freegma/**']  │
│ ☑ src/index.css (Tailwind 4)  + @source not "../freegma";     │
│ ☑ biome.json                  files.ignore + "freegma/**"     │
│ –  .vercelignore              (Vercel 설정 없음 — 건너뜀)        │
│ ✓ vite.config.ts              import한 파일만 번들 — 설정 불필요   │
│ [바뀔 내용 보기]                          [건너뛰기]  [적용]     │
└──────────────────────────────────────────────────────────┘
```
- 저장소를 확인해 **해당하는 것만** 제안하고, 바뀔 내용(diff)을 보여 준 뒤 **승인받아 한 번** 적용한다. `freegma/` 밖 파일을 쓰는 건 이 단계뿐이다(§12).

| 대상 | 이유 | 추가하는 것 |
|---|---|---|
| 번들러(Vite·Next·Metro) | `import`하지 않으면 원래 안 들어감 | 없음(«확인됨» 표시) |
| Tailwind 4 | 저장소 파일을 자동으로 훑어 클래스를 찾음 → `freegma/*.json` 문자열 때문에 CSS가 불어남 | `@source not "../freegma";` |
| Docker | `COPY . .`이면 이미지에 들어감 | `.dockerignore`에 `freegma/` |
| Vercel·Netlify·EAS | 업로드에 포함 | `.vercelignore`·`.easignore` 등 |
| CI(GitHub Actions 등) | 디자인 커밋만 있으면 빌드·배포 건너뜀 | `paths-ignore: ['freegma/**']` |
| 린터·포매터 | `freegma/` JSON을 검사·재포맷하지 않게 | ignore 목록 |
| npm 패키지 배포 | 패키지에 포함 | `package.json` `files` 또는 `.npmignore` |

- 이 파일들은 서비스 코드 쪽이라 freegma의 [커밋](`freegma/`만)에 들어가지 않는다. 따로 커밋하라고 안내한다(`chore: freegma/ 배포 제외 설정`).
- 프로젝트를 열 때마다 가볍게 다시 확인한다. 설정이 빠졌으면(예: 나중에 Dockerfile 추가) «배포 제외 설정이 빠졌습니다 [다시 설정]»을 띄운다. 설정에서 언제든 다시 열 수 있다.

### 2-2. 편집 화면
```
┌───────────────────────────────────────────────────────────────────────────┐
│ my-shop  ⎇ main          [디자인|프로토타입|개발]           ● 변경 3  [커밋] │ ← 헤더
├────────────┬────────────────────────────────────────────┬────────────────┤
│ ◆ 디자인 시스템 │ [이동][프레임][사각형][텍스트][이미지][컴포넌트] │ 속성        │ ← 도구 막대
│ 화면  [+화면]├────────────────────────────────────────────┤  위치·크기      │
│ ▾ 상품      │                                            │                │
│  ◐ 상품 상세 │                                            │  오토 레이아웃   │
│────────────│   ┌──────────┐    ┌──────────┐              │  채우기·선      │
│ 레이어      │   │ 상품 상세  │───▶│  장바구니  │ ← 프로토 연결  │  텍스트         │
│  ▾ 상품 상세 │   │ [담기]    │    │          │              │  토큰           │
│   ▸ 헤더   │   └──────────┘    └──────────┘              │   color.primary●│
│   ▸ 정보 카드│  ◐ 상품 상세 /products/:id  ✓ 장바구니 /cart │────────────────│
│────────────│                                            │ (개발 모드일 때)  │
│ 컴포넌트    │                                            │  [React+TW ▾]   │
│ 토큰       │                                            │  코드 · 토큰     │
│            ├────────────────────────────────────────────┤  간격 측정       │
│            │ 🤖 AI 연결됨 · 선택 공유 중 · 방금 AI가 2개 수정    100% │                │ ← 상태줄
└────────────┴────────────────────────────────────────────┴────────────────┘
```
- **헤더**: 프로젝트 이름, 현재 브랜치(누르면 브랜치 메뉴 — §2-2-1), 모드 전환, 마지막 커밋 이후 변경 수, **[커밋] 버튼**.
- **[커밋] 버튼 상태**: 변경 없음 → 꺼짐 / 변경 있음 → 켜짐(변경 수 표시) / git 병합 중·충돌 → «충돌 해결 필요»로 바뀌고 커밋을 막는다(§4).
- **왼쪽**: 맨 위 **디자인 시스템**(§2-5), 그 아래 **화면 목록**(도메인별 묶음·코드 상태, §2-7)과 [+ 화면], 레이어 트리·컴포넌트·토큰 탭. 컴포넌트·토큰 탭은 빠른 확인·끌어 놓기용이고, 고치는 곳은 디자인 시스템 화면이다.
- **캔버스**: 무한 캔버스, 프레임·도형·텍스트·이미지·컴포넌트 인스턴스. 오토 레이아웃(가로/세로, 간격, 패딩, 정렬, 채우기/고정/내용 맞춤).
- **오른쪽 패널**: 위에 **[속성 | ✦ AI]** 탭(⌘L로 전환). 속성 탭은 값 옆에 토큰 연결 표시 — 토큰에 연결된 값은 원시값이 아니라 토큰 이름으로 저장된다. 첫 탭 이름은 모드·화면에 따라 속성 / 인터랙션 / 코드(§7) / 시스템(§2-5). ✦ AI 탭은 §2-6.
- **모드 3개**: 디자인 / 프로토타입(화면 연결·전환, 미리보기 창) / 개발(§7).
- **상태줄**: MCP 연결 상태, 선택 공유 켜기·끄기, AI가 방금 바꾼 노드 수. 누르면 AI가 바꾼 노드를 캔버스에서 잠깐 강조한다(무엇이 바뀌었는지 사람이 따라갈 수 있게).

#### 2-2-1. 브랜치 메뉴 (헤더 ⎇ 칩)
```
⎇ main ▾
┌ 브랜치 · 서비스 저장소 전체 ─────────────┐
│ ✓ main                         지금   │
│   feature/checkout             2일 전  │
│   design/home-banner           5일 전  │
│ ──────────────────────────────────── │
│ + 새 브랜치 만들기…       지금 상태 그대로  │
│ ──────────────────────────────────── │
│ ⓘ 전환하면 서비스 코드도 함께 바뀝니다      │
│   (깨끗하지 않으면) 전환할 수 없습니다       │
│   · freegma 변경 4개 — 먼저 [커밋]       │
│   · 서비스 코드 변경 3개 — 터미널에서 정리   │
└──────────────────────────────────────┘
```
- 헤더의 브랜치는 **서비스 저장소 전체의 브랜치**다(`freegma/`가 같은 저장소에 있으므로). 그래서 «만들기»와 «전환»을 다르게 다룬다.

| 동작 | 허용 | 이유 |
|---|---|---|
| **새 브랜치 만들기** | 항상 | 파일이 바뀌지 않는다(`git switch -c`). 커밋 안 된 freegma 변경은 새 브랜치로 그대로 따라온다. 시안 A/B를 나눌 때 쓴다. 이름 제안 `design/<페이지>-<내용>` |
| **다른 브랜치로 전환** | **작업 트리 전체가 깨끗할 때만** | freegma 변경·서비스 코드 변경·병합 충돌이 하나라도 있으면 목록의 다른 브랜치를 끄고 이유를 보여 준다. 앱이 stash를 몰래 하지 않는다 |
| 전환 확인 | 한 번 묻기 | «서비스 코드도 ○○ 것으로 바뀝니다. 실행 중인 개발 서버가 다시 빌드되고 에디터에 열린 파일도 바뀝니다» |
| 병합·pull·push·삭제·이름 변경 | 앱에서 안 함 | 터미널·AI·GitHub 몫(원칙 2: git을 흉내 내지 않음) |

- 전환하면 프로젝트를 통째로 다시 읽고 되돌리기 기록을 비운다(§4 «브랜치 전환»과 같음). ✦ AI 대화는 브랜치마다 따로 둔다(`freegma/.cache/chat/<브랜치>/`). 새 브랜치를 만들 때는 지금 대화를 이어 간다.
- 터미널에서 브랜치를 바꿔도 지금처럼 파일 감시로 따라간다.
- git 저장소가 아니면 칩은 «git 없음»이고 메뉴가 열리지 않는다.

### 2-3. 커밋 창
```
┌ 커밋 ─────────────────────────────────────────────┐
│ 변경 (freegma/)                                     │
│  + 홈 / 메인 배너                                   │
│  ~ 상품 상세 / 정보 카드   간격, 버튼 색              │
│  − 상품 상세 / 옛 시안                               │
│  ◆ color.primary  #3B82F6 → #2563EB   (디자인 시스템) │
│                                                   │
│ 메시지 (자동 작성 · 고칠 수 있음)                      │
│ ┌───────────────────────────────────────────────┐ │
│ │ design(상품 상세): 정보 카드 수정, 메인 배너 추가    │ │
│ │                                               │ │
│ │ 추가                                           │ │
│ │ - 홈 / 메인 배너 …                              │ │
│ └───────────────────────────────────────────────┘ │
│ 작성자: 홍길동 <me@example.com>  (git 설정)          │
│                                 [취소]  [커밋]     │
└───────────────────────────────────────────────────┘
```
- 변경 항목을 누르면 캔버스에서 그 프레임으로 이동한다. 디자인 시스템 항목(◆)은 디자인 시스템 화면의 그 토큰·컴포넌트로 이동한다.
- 작성자 정보가 git에 없으면 이 자리에 이름·이메일 입력칸이 나온다(처음 한 번, §5-3).
- 커밋이 실패하면(예: pre-commit 훅) git 출력을 그대로 보여 주고 창을 닫지 않는다.
- 성공하면 짧은 알림(«커밋됨 a1b2c3d»)만 띄운다.

### 2-4. 범위
- **Figma와 다르게 하는 것**: 실시간 협업·댓글·공유 링크·클라우드 저장·로그인 없음. 로고·이름·아이콘·서체는 자체 것을 쓴다.
- **1차 범위 밖(2차)**: 벡터 펜 툴·불리언 연산, 변형(variant) 속성 편집 UI, 스마트 애니메이트, 플러그인, 외부 툴 가져오기, [푸시] 버튼, 앱 안 병합·pull, 커밋 기록 보기. (브랜치 만들기·깨끗할 때 전환은 1차 — §2-2-1)

### 2-5. 디자인 시스템 화면 (상세: `docs/design-system.md` §3)
```
┌────────────┬──────────────────────────────────────────┬────────────────┐
│ 디자인 시스템 │ ◆ my-shop 디자인 시스템   [✦ AI가 읽는 형태 보기] │ color.primary   │
│ ◆ my-shop  │────────────────────────────────────────────│ 참조 [brand.600▾]│
│ 페이지      │ 색                                           │ 값   #2563EB    │
│  홈        │  기초값  ▇▇▇▇▇▇▇  (직접 쓰지 않음)               │ 용도 (AI가 읽음) │
│  상품 상세   │  의미 토큰  ■ color.primary → brand.600  용도… │ [가장 중요한 …] │
│────────────│ 글자   Display / Heading / Title / Body / …  │ 피할 곳         │
│ 개요·원칙   │ 간격 · 모서리 · 그림자                          │ [긴 본문 글자…]  │
│ 기초: 색 …  │ 컴포넌트  Button [primary·ghost·inverse ×      │ 사용처 12곳      │
│ 기본 컴포넌트 │          기본·눌림·비활성] 쓸 때 / 피할 때       │  · 장바구니 담기…│
│ 서비스 컴포넌트│ AI 규칙  원시값: [경고 후 반영|거절]             │ 저장될 JSON     │
└────────────┴──────────────────────────────────────────┴────────────────┘
```
- 왼쪽 «디자인 시스템»을 누르면 가운데가 캔버스 대신 **시스템 문서**(위에서 아래로 스크롤)로 바뀌고, 왼쪽 아래는 시스템 목차가 된다.
- 색은 **기초값**(팔레트, 직접 쓰지 않음)과 **의미 토큰**(디자인에서 쓰는 이름)으로 나눠 보여 준다. 글자는 **글자 스타일** 단위로, 컴포넌트는 **변형 × 상태 견본**과 «쓸 때 / 피할 때»로 보여 준다.
- 항목을 누르면 오른쪽에서 값·용도·피할 곳을 고친다. 고치면 쓰는 모든 페이지에 바로 반영되고, 오른쪽에 사용처(레이어 목록)가 보인다. 브랜드 대표 색을 바꾸면 brand 단계가 다시 만들어진다.
- 용도·피할 곳 문장은 그대로 AI에게 전달된다(§6 `get_design_system`). [AI가 읽는 형태 보기]로 AI가 받는 요약과, AI가 토큰 밖 값을 보냈을 때의 응답(경고/거절)을 미리 볼 수 있다.
- 개발 모드에서는 오른쪽이 토큰 내보내기 미리보기(§7)가 된다.

### 2-6. ✦ AI 채팅 탭 (오른쪽 [속성 | ✦ AI], ⌘L)
```
┌ [속성 | ✦ AI ⌘L] ─────────────────┐
│ ┌──────────────────────────────┐ │
│ │ # 정보 카드                     │ │ ← 보낼 때 대상(선택)이 같이 붙음
│ │ 간격 좀 더 넓혀줘                 │ │
│ └──────────────────────────────┘ │
│ 간격을 spacing.4 (16) → spacing.5  │
│ (20)로 바꿨어요.                    │
│ get_selection · get_design_system │ ← 쓴 MCP 도구
│ update_nodes ✓ 검사 통과            │
│ ✦ 1개 수정     [보기] [이 답변 되돌리기]│
│──────────────────────────────────│
│ 대상: [# 정보 카드]  선택한 레이어      │
│ (간격 좀 더 넓혀줘) (토큰 맞게 썼어?)   │ ← 대상에 맞는 제안
│ [디자인에 대해 묻거나 시키기… ⏎      ] │ ← Enter 보내기, ⇧Enter 줄바꿈
└──────────────────────────────────┘
```
- **왜 앱 안 채팅인가**: 선택한 레이어가 대상으로 자동으로 붙고, 바뀐 곳이 캔버스에 바로 강조되고, 답변 하나를 통째로 되돌릴 수 있다. 터미널이 없는 사람도 쓸 수 있다. 코드까지 함께 고치는 일은 지금처럼 터미널 Claude Code + MCP로 한다(**디자인은 채팅 탭, 코드는 터미널**).
- **왜 오른쪽인가**: 왼쪽은 대상을 고르는 곳(화면 목록·레이어 트리)이라 채팅하면서도 계속 써야 한다. 오른쪽은 «선택한 것에 무언가 하는 곳»이라 채팅과 성격이 같다. (2차: AI 패널을 따로 떼어 속성과 나란히)
- **입력**: 보내기 버튼 없이 **Enter로 보낸다**(⇧Enter 줄바꿈, 한글 조합 중 Enter는 보내지 않음). Claude Code와 같은 방식.
- **대상(맥락)**: 보낼 때 지금 선택을 같이 보낸다 — 레이어를 골랐으면 그 레이어, 디자인 시스템 화면이면 고른 토큰·컴포넌트(없으면 시스템 전체), 아무것도 안 골랐으면 지금 페이지. 입력창 위에 칩으로 보이고 ✕로 뺄 수 있다.
- **묻기와 시키기**: 질문(«이 화면 primary 버튼 몇 개야?»)이면 도구로 읽기만 하고 답한다. 수정은 답변에 **«✦ N개 수정»** 이 붙을 때만 생긴다. [보기]는 바뀐 레이어로 이동·강조, **[이 답변 되돌리기]** 는 그 답변의 수정 전부를 한 번에 되돌린다(답변 하나 = 되돌리기 한 단위, op 묶음).
- **규칙을 지킨다**: 같은 MCP 검사를 거치므로 시스템 밖 값을 쓰지 않고, 규칙에 걸리면 고치지 않고 이유를 말한다(예: «primary는 화면당 1개라 바꾸지 않았어요»).
- **고치는 범위**: 기본은 «대상 + 그 프레임». 다른 화면이나 **디자인 시스템**을 바꾸면 답변에 «◆ 디자인 시스템 변경 — 모든 화면에 영향»을 표시한다.
- **실행**: 사용자 PC의 Claude Code를 대화 세션으로 띄운다(`docs/spec.md` §4). 허용 도구는 freegma MCP + 저장소 읽기. 서비스 코드 수정·셸 실행은 하지 않는다. 사용자 본인의 Claude 로그인·요금제를 쓴다.
- **대화 기록**: `freegma/.cache/chat/`(git 제외). 디자인 결과는 평소처럼 [커밋]으로 남고 대화는 커밋하지 않는다. 앱을 다시 열면 마지막 세션을 이어 간다(세션 재개).
- **Claude 미연결**: 탭은 보이고 «Claude Code 연결 필요 · 연결 명령 복사»만 보여 준다(«저장소에서 가져오기»와 같은 기준).
- 상태줄 «AI 연결됨» 팝오버에 [✦ AI 탭 열기 ⌘L]. 채팅 탭에서 고친 것도 상태줄 «방금 AI가 N개 수정»과 레이어 트리 ✦ 표시에 똑같이 잡힌다.

### 2-7. 화면 · 도메인 · 코드 (새 화면이 코드가 되는 길)
**기준 단위는 «화면」 하나다: 화면 = 라우트 하나 = 코드 파일 하나.** 사람이 따로 만들고 관리하는 묶음(페이지·보드)은 두지 않는다. 코드에는 그런 묶음이 없어서, 두면 «이 화면은 어느 묶음에?»를 코드와 따로 맞춰야 하기 때문이다.

| freegma | 뜻 | 코드와의 관계 |
|---|---|---|
| **화면** (`role: "screen"`) | 최상위 프레임 중 코드의 화면이 될 것 | **라우트 하나 + 화면 파일 하나** |
| **시안** (`role: "draft"`, `draftOf`) | 특정 화면에 붙은 비교·실험용 프레임(시안 B, C…) | 코드로 가지 않음. 캔버스에서 원본 옆에 붙어 보임 |
| **도메인** | 화면의 **꼬리표**(상품·주문·마이 …). 그릇이 아님 | 기본은 코드에 없음. 기능 폴더(`src/features/order/`)·라우트 그룹(`app/(order)/`)을 쓰는 저장소면 그것에 대응(감지 시) |
| (지정 안 함) | 작업용 최상위 프레임 | 코드로 가지 않음, 언제든 «화면»으로 지정 |

**도메인** — 라우트 첫 단어에서 자동 제안한다(`/products/:id` → 상품, `/cart`·`/checkout`·`/coupons` → 주문, `/my/…` → 마이). 어긋나면 화면의 «도메인» 칸에서 바꾸고, 새 이름을 쓰면 새 도메인이 된다(따로 만드는 버튼 없음). AI도 «주문 도메인 화면들 버튼 맞춰줘»처럼 범위로 쓴다.

**왼쪽 화면 목록과 캔버스**
```
화면                          [+ 화면]
 ▦ 전체 보기                        4
 ▾ 상품                             1
    ◐ 상품 상세     /products/:id
 ▾ 주문                             2
    ○ 쿠폰함        /coupons
       – 쿠폰함 시안 B   시안
    ✓ 장바구니      /cart
```
- 도메인을 고르면 캔버스에 **그 도메인의 화면과 시안만** 보인다(화면이 많아도 가볍고 찾기 쉬움). 화면을 누르면 그 도메인으로 가서 그 화면에 맞춰 확대한다.
- **전체 보기**: 모든 화면을 도메인별 줄로 펼친다. 프로토타입 모드의 **«흐름 보기」** 가 이것이다(도메인을 넘는 연결선까지 보임).
- 캔버스 위치는 도메인 안에서 화면 → 그 시안 순으로 자동 배치한다(사람이 위치를 관리하지 않음).

**새 화면 만들기** — «화면» 옆 **[+ 화면]**(또는 프레임 도구 → «+ 새 화면…», ✦ AI «쿠폰함 화면 만들어줘»)
```
┌ 새 화면 ────────────────────────────────────────────┐
│ 역할 [● 화면 — 코드의 라우트가 됨 | 시안 — 기존 화면에 붙음]     │
│ 이름 [쿠폰함        ]          크기 [데스크톱 1440×1024 ▾]    │
│ 라우트 [/coupons    ]          도메인 [주문 ▾] ← 라우트에서 제안 │
│   라우터      React Router (src/router.tsx 감지)            │
│   코드 파일   src/pages/CouponsPage.tsx                    │
│   라우트 등록 src/router.tsx 에 라우트 추가                    │
│ 파일은 지금 만들지 않음 — 디자인 후 [✦ 코드에 반영]으로          │
└────────────────────────────────────────────────────┘
```
- 라우트·파일은 `spec.json`과 저장소의 라우터 방식으로 제안한다: React Router(`src/pages/<이름>Page.tsx` + 라우터 파일에 등록), Next.js App Router(`app/<경로>/page.tsx`, 파일 기반), Expo Router(`app/<경로>.tsx`, 파일 기반). 같은 라우트를 두 화면이 쓰면 막는다.
- 역할을 «시안」으로 고르면 라우트·도메인 대신 «어느 화면의 시안인가」를 고른다. 기존 화면을 복제해 시작하려면 그 화면 오른쪽 패널의 **[＋ 시안 만들기]**. 시안을 원본으로 바꾸는 «이 시안으로 교체」는 2차.
- 디자인 시스템 컴포넌트로 뼈대(내비게이션 + 제목)를 만들어 둔다.
- 같은 라우트의 다른 크기(데스크톱·모바일 웹 = 반응형)는 2차: 한 화면에 크기별 프레임을 묶는 «브레이크포인트»로.

**코드 상태** — 캔버스 프레임 이름·레이어 트리·개발 모드 «화면 목록»에 표시한다.

| 표시 | 뜻 | 판단 |
|---|---|---|
| ○ 코드 없음 | 화면인데 아직 반영 안 됨 | 서비스 저장소에 이 화면 id의 `Design-Ref` 커밋이 없음 |
| ◐ 디자인이 더 새로움 | 마지막 반영 이후 디자인이 바뀜 | 마지막 `Design-Ref` 커밋 이후 이 프레임 파일이 바뀜 → 바뀐 것 목록(노드 단위, 커밋 메시지와 같은 비교) |
| ✓ 코드 최신 | 지금 디자인이 코드에 반영됨 | 마지막 `Design-Ref`가 이 프레임의 최신 디자인 커밋을 가리킴 |
| – 시안 | 코드로 가지 않음 | `role: "draft"` |

**코드에 반영** — 앱은 코드를 쓰지 않는다(§7). 개발 모드에서 화면을 고르고 **[✦ 코드에 반영…]**
```
① freegma: 화면 만들기 → 디자인 → [커밋]        design(상품 상세): 쿠폰함 추가
② 개발 모드 [✦ 코드에 반영] → 반영 꾸러미 미리보기 → [✦ 터미널에서 Claude로 반영]
   └ 터미널에서 사용자의 Claude Code를 대화형으로 열고 요청문을 넣어 줌(파일을 고칠 때마다 평소처럼 확인)
③ Claude Code: MCP get_handoff(화면) → 파일 생성·라우트 등록·화면 이동 연결 → 코드 커밋
     feat(coupons): 쿠폰함 화면
     Design-Ref: freegma@a1b2c3d screen:n_7k2p
④ freegma: 서비스 저장소 git log의 Design-Ref를 읽어 상태 갱신 → ✓ 코드 최신
```
- **반영 꾸러미**(`get_handoff`): 대상 파일(새로 만들기/고치기)·라우트·라우트 등록 위치, 마지막 반영 이후 **바뀐 것만**(처음이면 전체), 생성 코드(개발 모드의 결정적 생성), 쓰는 컴포넌트와 import(코드가 없는 서비스 컴포넌트는 «새로 만들 것»), 쓰는 토큰(코드 쪽 토큰 파일과 다르면 경고), 화면 이동(프로토타입 연결 → 라우트), 남는 일(상태·데이터 로직은 TODO). AI가 «무엇을 어디에 어떻게»를 추측하지 않게 하는 게 목적이다.
- 이 화면의 디자인 변경이 아직 커밋되지 않았으면 «먼저 커밋»을 권한다(Design-Ref가 가리킬 커밋이 있어야 하므로).
- 터미널을 직접 쓰는 사람은 [요청문 복사]로 같은 지시를 붙여 넣으면 된다. Claude 미연결이면 [터미널에서 Claude로 반영]은 꺼진다.
- 반영 기록은 **코드 커밋의 `Design-Ref` 꼬리말 하나**로만 한다. freegma 파일에 «반영됨»을 따로 쓰지 않아 두 히스토리가 꼬이지 않고, 같은 저장소라 브랜치·PR과 함께 움직인다.
- **코드 → 디자인**(이미 코드에 있는 화면을 디자인으로 가져오기)은 2차. 1차는 기존 화면에 라우트·파일 연결만 지정할 수 있다.

## 3. 파일 형식 (Git 친화)
```
my-shop/                      ← 서비스 저장소 루트
  src/ …                      ← 서비스 코드 (앱은 읽기만, §12)
  freegma/
    project.json              ← 프로젝트 설정: 포맷 버전, 플랫폼(web/mobile), 도메인 순서
    spec.json                 ← 개발 스펙 프로필(§7) — 프로젝트 만들 때 선택
    system/                   ← 디자인 시스템 (docs/design-system.md §4) — 프로젝트 만들 때 생성
      system.json             ← 이름·버전·서체·원칙·AI 규칙(rawValues: warn|reject)
      tokens/
        primitives.tokens.json  ← 기초값(직접 쓰지 않음)
        color.tokens.json       ← 의미 색 → 기초값 참조 + $description(용도)·avoid — W3C DTCG 형식
        typography.tokens.json  ← 서체·크기 단계·글자 스타일
        spacing.tokens.json  radius.tokens.json  shadow.tokens.json
      components/
        button.fg.json        ← 컴포넌트 원본 + 속성·변형·상태 + 사용 규칙(usage) + 코드 연결
      DESIGN_SYSTEM.md        ← AI용 요약(자동 생성, 커밋함)
    screens/
      product-detail.fg.json  ← 최상위 프레임 하나 = 파일 하나 (화면: role·route·domain·code)
      coupons.fg.json
      coupons.draft-b.fg.json ← 시안(draftOf로 원본 화면을 가리킴)
    assets/
      img-7f3a.png            ← 이미지는 내용 해시 이름
    .cache/                   ← 캐시·썸네일 (.gitignore에 자동 추가)
```
- **시스템과 화면을 폴더로 나눈다.** 화면은 묶음 폴더 없이 `screens/`에 평평하게 둔다(도메인은 파일 안 꼬리표라 바꿔도 파일이 옮겨지지 않음). 개정 1의 `freegma/tokens/`·`freegma/components/`는 `freegma/system/` 아래로 옮겼다. 노드의 토큰 참조 문법(`"{color.primary}"`)은 그대로다.
- **최상위 프레임 하나 = 파일 하나.** 한 화면 수정이 한 파일 diff로 끝나고, 브랜치 간 충돌도 화면 단위로 줄어든다.
- **안정된 출력**: 키 순서 고정, 2칸 들여쓰기, 숫자는 소수 둘째 자리까지 반올림, 기본값인 속성은 쓰지 않는다. 같은 디자인은 항상 같은 바이트로 저장된다.
- **노드 id**: 짧은 무작위 id(`n_8k2m`)로 고정. 이름이 바뀌어도 id는 그대로라 diff가 «이름 변경»으로 보이고, 커밋 메시지(§5-2)도 id로 변경을 추적한다.
- **파일 이름**: 라우트(없으면 프레임 이름)에서 영문 슬러그를 만든다(한글은 음역 또는 id). 이름을 바꿔도 파일 이름은 그대로 둔다(diff를 작게).
- **사람이 읽을 수 있게**: 노드 예시
  ```json
  { "id": "n_8k2m", "type": "frame", "name": "정보 카드",
    "layout": { "dir": "col", "gap": "{spacing.4}", "pad": "{spacing.6}" },
    "fill": "{color.surface}",
    "children": [ { "id": "n_2pq1", "type": "instance", "of": "button",
                    "props": { "label": "장바구니 담기", "variant": "primary" } } ] }
  ```
- **노드 칸**: 노드 타입은 `frame`·`rect`·`text`·`image`·`instance`. `id`·`type`은 필수, `name`은 선택(없으면 컴포넌트 이름·타입·글자 내용을 대신 보여 줌). 모르는 키는 거절한다(오타를 바로 알리기 위해). 스키마: `packages/schema/src/node.ts`.
- **화면 프레임**(§2-7): 최상위 프레임에 역할·라우트·코드 파일을 둔다. 반영 여부는 여기 쓰지 않는다(코드 커밋의 Design-Ref로 판단).
  ```json
  { "id": "n_7k2p", "type": "frame", "name": "쿠폰함",
    "role": "screen", "route": "/coupons", "domain": "주문",
    "code": { "file": "src/pages/CouponsPage.tsx" },
    "layout": { "dir": "col" }, "children": [ … ] }
  ```
- **이미지**: `assets/`에 원본 파일로. 커지면 Git LFS를 쓰도록 안내만 한다(1차는 강제하지 않음).
- **포맷 버전**: `project.json`의 `formatVersion`. 앱이 더 높은 버전을 만나면 읽기 전용으로 연다. 낮은 버전은 열 때 변환하고 변환 사실을 알린다.

## 4. 프로세스 구조
```
freegma (앱, Electron 메인 프로세스)
 ├ ProjectStore   : 파일 읽기·쓰기, 문서 모델, 되돌리기 기록
 ├ FileWatcher    : 바깥(AI·git checkout·에디터)에서 바뀐 파일 감지 → 다시 읽기
 ├ GitBridge      : 설치된 git 실행(status·diff·commit·show HEAD). 사용자 git 설정·훅 그대로
 ├ ChangeDiffer   : HEAD의 freegma/ ↔ 지금 상태를 노드 id 단위로 비교 → 변경 목록·커밋 메시지(§5-2)
 ├ McpServer      : localhost 전용 MCP 서버(§6). 앱이 떠 있을 때의 쓰기 창구
 └ CodeGen        : 노드 → 중간 표현 → 스펙 어댑터(§7)
        │
 렌더러 (React)
 ├ 캔버스 렌더러(§8)
 ├ 패널: 레이어·속성·토큰·개발, 디자인 시스템 화면
 ├ 커밋 창
 └ 프로토타입 미리보기 창

freegma-mcp (CLI, 앱 없이도 동작)
 └ 같은 ProjectStore·ChangeDiffer·CodeGen을 쓰는 headless 모드. 앱이 떠 있으면 앱의 McpServer로 요청을 넘긴다.
```
- **쓰는 쪽은 하나.** 앱이 떠 있으면 모든 MCP 쓰기는 앱을 거친다 → 앱의 되돌리기 기록에 남고(Ctrl+Z로 AI 수정 취소 가능), 화면이 바로 갱신된다. 앱이 없으면 `freegma-mcp`가 파일에 직접 쓴다.
- **저장**: 편집 후 300ms 모아서 자동 저장. 임시 파일에 쓰고 이름 바꾸기(원자적 쓰기)로 반쯤 쓴 파일이 남지 않게 한다. 저장과 커밋은 별개다(저장은 자동, 커밋은 버튼).
- **바깥 변경**: FileWatcher가 바뀐 파일만 다시 읽어 해당 프레임만 갱신한다. 앱에 아직 저장 안 된 편집이 있는 파일이 바깥에서 바뀌면 덮어쓰지 않고 알린다(«디스크 것 쓰기 / 내 것 유지»).
- **브랜치 전환·pull**: 앱의 브랜치 메뉴(§2-2-1)나 터미널에서 하면 FileWatcher가 바뀐 파일을 다시 읽는다. 되돌리기 기록은 그 시점에 비운다.
- **병합 충돌**: git이 충돌 표시(`<<<<<<<`)를 남긴 파일은 열지 않고, 헤더에 «충돌 해결 필요»를 띄운다. 1차는 파일별로 «내 것 / 상대 것 / 둘 다 프레임으로 나란히» 중 고르게 한다. JSON 구조 인식 병합 드라이버(`.gitattributes merge=freegma`)는 2차.
- **되돌리기 vs 버전**: 되돌리기는 앱 세션 안(메모리). 그보다 오래된 이력은 Git.
- **Git은 직접 구현하지 않는다.** 설치된 `git`을 실행한다. 사용자 인증·서명·훅이 그대로 동작한다. git이 설치돼 있지 않으면 시작 화면에서 설치를 안내한다.

## 5. 커밋 (확정)

### 5-1. [커밋] 버튼
- **[커밋] = 이 디자인 프로젝트(`freegma/`)의 변경 전부를 한 커밋으로.** `git add -A freegma/` → `git commit`. 저장소의 다른 파일(서비스 코드)은 stage하지 않는다. 사람이 미리 stage해 둔 코드 파일도 이 커밋에 섞이지 않게 `git commit -- freegma/`처럼 경로를 한정한다.
- 순서: 저장 안 된 편집 저장 → 변경 목록·메시지 계산 → 커밋 창(§2-3) → 커밋.
- 앱은 자동으로 커밋하지 않는다. 버튼을 눌렀을 때만.
- 푸시는 1차 범위 밖(2차 [푸시] 버튼, §5-3).

### 5-2. 커밋 메시지
- **앱이 변경 내용을 보고 자동으로 초안을 만든다(AI 없이, 항상 같은 규칙).** 사람은 고치거나 그대로 커밋한다.
- 비교 기준은 마지막 커밋(`HEAD`)의 `freegma/` 파일과 지금 파일. 파일 diff가 아니라 **노드 id 단위로 비교**해서 «무엇이 바뀌었는지»를 디자인 말로 쓴다.
- 형식: 첫 줄은 Conventional Commits 꼴, 본문은 변경 목록.
  ```
  design(상품 상세): 정보 카드 수정, 메인 배너 추가

  추가
  - 홈 / 메인 배너
  수정
  - 상품 상세 / 정보 카드: 간격, 버튼 색
  삭제
  - 상품 상세 / 옛 시안
  디자인 시스템
  - color.primary: #3B82F6 → #2563EB
  - spacing.6 추가 (24)
  - button: variant «ghost» 추가
  - button 사용 규칙: 설명 수정
  ```
- 첫 줄 규칙
  - 접두어는 `design`. 디자인 시스템(토큰·글자 스타일·컴포넌트·AI 규칙)만 바뀌면 `design(system)`.
  - 괄호 안 범위: 바뀐 화면이 한 도메인이면 그 도메인 이름, 여럿이면 생략.
  - 요약: 가장 큰 변경 1~2개를 «무엇 + 동사»로. 나머지는 «외 N건».
  - 50자 안팎에서 자른다.
- 본문 규칙
  - 묶음 순서: 추가 → 수정 → 삭제 → 디자인 시스템. 비어 있는 묶음은 쓰지 않는다.
  - 화면은 «도메인 / 화면 이름»으로. 새 화면은 «추가 — 쿠폰함 (화면 /coupons)»처럼 라우트를 함께. 수정은 바뀐 속성 종류만(간격·색·글꼴·크기·위치·텍스트·이미지), 값까지는 쓰지 않는다.
  - 디자인 시스템 값은 디자인 전체에 영향을 주므로 **바뀐 값을 전·후로** 쓴다. 용도 설명만 바뀌면 «설명 수정».
  - 항목이 20개를 넘으면 앞 20개만 쓰고 «외 N건».
- **AI 요약은 선택.** AI 에이전트에게 맡기고 싶으면 MCP `get_changes`로 같은 변경 목록을 받아 의도를 담은 메시지로 직접 커밋할 수 있다. 앱 안에는 AI를 넣지 않는다.

### 5-3. 인증 (로그인 없음)
- **앱에는 로그인·계정이 없다.** 커밋은 내 PC의 저장소에 기록하는 일이라 인증이 필요 없다. 작성자는 git 설정의 `user.name`·`user.email`을 쓴다.
- 작성자 정보가 설정돼 있지 않으면 처음 커밋할 때 커밋 창에서 이름·이메일을 한 번 묻고, 그 저장소 설정(`git config --local`)에만 저장한다.
- **푸시(2차)는 이 PC의 git 인증을 그대로 쓴다**(SSH 키, credential helper, `gh auth`). 앱이 git을 실행하므로 터미널에서 푸시가 되면 앱에서도 된다. 앱은 토큰을 받거나 저장하지 않는다.

## 6. MCP 인터페이스
- **연결**: Claude Code 등에 `freegma-mcp`를 stdio 서버로 등록(`claude mcp add freegma -- freegma-mcp --project ./freegma`). 앱이 떠 있으면 내부적으로 앱에 붙는다. 앱 설정 화면에 이 명령을 복사 버튼과 함께 보여 준다.
- **도구 목록(1차)**

| 도구 | 하는 일 |
|---|---|
| `get_design_system` | 디자인 시스템 요약: 원칙·AI 규칙, 의미 토큰(참조·값·용도·피할 곳), 글자 스타일, 컴포넌트(속성·쓸 때·피할 때·접근성). **디자인 시작 전에 먼저 부른다**(MCP 서버 설명에 명시). `docs/design-system.md` §5-2 |
| `get_project` | 도메인별 화면 목록(라우트·코드 상태·시안), 디자인 시스템 이름·버전, 스펙 프로필 |
| `get_handoff` | 화면 하나의 반영 꾸러미(§2-7): 파일·라우트·등록 위치, 마지막 반영 이후 바뀐 것, 생성 코드, 컴포넌트 import, 토큰, 화면 이동, 남는 일, Design-Ref 값 |
| `get_selection` | 사람이 앱에서 지금 고른 노드(선택 공유가 켜져 있을 때만) |
| `get_nodes` | id로 노드 트리 읽기(깊이 지정). 큰 트리는 요약 + 이어 읽기 |
| `find_nodes` | 이름·타입·토큰 사용·텍스트로 찾기 |
| `create_nodes` / `update_nodes` / `delete_nodes` | 노드 만들기·고치기·지우기. 여러 개를 한 번에, 한 번의 되돌리기 단위로 |
| `scan_repo_values` / `get_import_draft` / `finish_import` | 저장소에서 가져오기 전용: 서비스 저장소 값 집계(읽기만), 초안 읽기·제출(`docs/design-system.md` §2-2) |
| `get_tokens` / `set_tokens` | 토큰 읽기·추가·수정(용도 `$description`·`avoid` 포함, 의미 토큰은 기초값 참조만) |
| `get_components` / `update_components` / `instantiate` | 컴포넌트 목록·속성·변형·사용 규칙 읽기·고치기, 인스턴스 배치 |
| `render_image` | 프레임·노드를 PNG로 렌더해서 돌려줌(AI가 결과를 눈으로 확인) |
| `get_changes` | 마지막 커밋 이후 변경 목록(§5-2와 같은 내용, 노드 id 포함) |
| `lint` | 디자인 시스템 규칙(원시값·단계 밖 값·기초값 직접 참조·글자 스타일·비슷한 컴포넌트·사용 제한·설명 누락, `docs/design-system.md` §5-4), 깨진 컴포넌트 참조, 겹침·잘림 검사 |
| `generate_code` | 노드를 스펙 프로필에 맞는 코드로(§7) |

- **입력 검증**: 모든 쓰기는 스키마 검증 후 반영. 틀린 입력은 무엇이 틀렸는지 돌려준다(AI가 스스로 고칠 수 있게).
- **디자인 시스템 검사**: `create_nodes`·`update_nodes`는 쓰기 전에 시스템 규칙으로 검사한다. 토큰 밖 원시값은 `system.json`의 `rules.rawValues`에 따라 **경고 후 반영**(기본) 또는 **거절**하고, 어느 쪽이든 바꿀 토큰을 `suggest`로 돌려준다. 사람이 캔버스에서 고칠 때는 표시만 한다.
- **AI 친화 출력**: 트리는 토큰 이름·컴포넌트 이름 중심으로 돌려주고 좌표·기본값은 줄인다(토큰 절약).
- **commit 도구는 두지 않는다.** AI 에이전트는 이미 git을 쓸 수 있다. 앱이 흉내 내지 않는다.
- **같은 도구, 두 입구.** 터미널 Claude Code와 앱 안 ✦ AI 탭(§2-6)은 같은 MCP 도구·검사를 쓴다. 채팅 탭에서 온 호출은 «답변 id»를 달고 와서, 앱이 그 답변의 op를 한 묶음(되돌리기 한 단위)으로 묶는다.
- **선택 공유**는 기본 켜짐, 상태줄에서 끌 수 있다.

## 7. 개발자 모드 (스펙 맞춤 코드)
- **스펙 프로필** `freegma/spec.json` — **프로젝트를 만들 때 고른 플랫폼·개발 스펙으로 정해진다**(§2-1-1). 개발 모드는 이 파일만 보고 코드를 낸다.
  ```json
  { "platform": "web",
    "target": "react", "language": "typescript",
    "styling": "tailwind@4",
    "components": { "library": "shadcn", "dir": "src/components/ui" },
    "tokens": { "output": "src/styles/tokens.css", "format": "css-vars" },
    "conventions": "docs/frontend-conventions.md" }
  ```
  - 만들 때는 플랫폼·스펙만 고르고, 나머지 칸(컴포넌트 폴더·토큰 출력 경로 등)은 저장소를 읽어 채운다. 못 채운 칸은 기본값으로 두고 개발 모드 첫 화면에서 확인하게 한다.
  - 개발 모드 패널 위의 스펙 표시(`[React+TW ▾]`)는 지금 스펙을 보여 주고, 누르면 설정으로 간다(바꾸면 `spec.json`이 바뀌고 커밋 대상이 된다).
- **1차 스펙 어댑터(플랫폼마다 하나)**

| 플랫폼 | 1차 | 이후 |
|---|---|---|
| 웹 | React + Tailwind CSS | React + CSS Modules, Vue |
| 모바일 앱 | React Native (제안, §16-4) | Flutter, SwiftUI, Jetpack Compose |

  - React Native를 모바일 1차로 제안하는 이유: 레이아웃이 flexbox라 웹과 같은 중간 표현(IR)을 거의 그대로 쓰고, 컴포넌트 구조도 React와 같아 어댑터를 하나 더 만드는 비용이 가장 작다.
- **생성 3단계**
  1. **중간 표현(IR)**: 노드 트리 → 레이아웃(flex/grid)·스타일·토큰 참조·텍스트·이미지로 바꾼 중립 트리. 절대 좌표는 오토 레이아웃이 없는 곳에서만 쓴다.
  2. **스펙 어댑터**: IR → 대상 코드(위 표). 토큰은 값이 아니라 이름으로 낸다(`bg-primary`, `var(--color-primary)`).
  3. **컴포넌트 연결**: 디자인 컴포넌트에 코드 컴포넌트가 연결돼 있으면 그 컴포넌트의 import·props로 낸다.
     ```json
     // system/components/button.fg.json 일부
     "code": { "import": "@/components/ui/button", "name": "Button",
               "props": { "variant": "$variant", "children": "$label" } }
     ```
- **역할 나눔**: 1·2단계는 **결정적**(같은 입력 → 같은 출력, AI 없이). AI는 연결 제안(«이 디자인 컴포넌트는 `src/components/ui/button.tsx`와 같아 보임»), 이름 짓기, 상태·이벤트 로직, 기존 코드에 끼워 넣기를 맡는다.
- **코드는 앱이 쓰지 않는다.** 앱은 코드를 보여 주고 복사하게만 한다. 서비스 코드에 반영하고 커밋하는 건 AI 에이전트·사람 몫이다(§5-1과 같은 선).
- **토큰 내보내기**: `system/tokens/` → 프로필의 `tokens.output` 형식으로 만든 내용을 보여 준다. 코드 쪽 토큰 파일과 값이 다르면 알린다(덮어쓰지 않음).
- **개발 패널**: 아무것도 안 고르면 **화면 목록과 코드 상태**(○ ◐ ✓, §2-7)와 토큰 내보내기. 노드를 고르면 그 노드가 속한 화면의 상태·[✦ 코드에 반영…], 생성 코드, 쓰인 토큰, 연결된 컴포넌트, 간격·크기 측정, «복사».

## 8. 캔버스 렌더링 (반응성의 핵심)
- **1차는 DOM + CSS 렌더**를 쓴다(웹페이지처럼 HTML 요소로 그리는 방식). 오토 레이아웃이 그대로 flexbox가 되므로 «캔버스에 보이는 것 = 코드로 나올 것»이 맞고, 텍스트 줄바꿈도 브라우저와 같다. 캔버스 이동·확대는 바깥 컨테이너 `transform` 하나로만 한다.
- 화면 밖 프레임은 DOM에서 빼고 썸네일(캐시)로 대신 그린다. 확대가 많이 줄면 썸네일만 그린다.
- 선택 상자·가이드·간격 표시는 DOM 위에 얹은 별도 canvas 한 장에 그린다.
- 편집 중에는 바뀐 노드만 다시 그린다(노드 id 단위 메모이즈).
- §9 목표를 못 맞추면 CanvasKit(Skia WASM, 전용 그래픽 엔진) 렌더러로 바꾼다. 그래서 문서 모델과 렌더러 사이를 «노드 → 그리기 명령» 경계로 분리해 둔다. 이 판단은 구현 중 실측으로 내린다(사용자 결정 불필요).
- `render_image`(MCP)도 같은 렌더러를 화면 밖 창에서 돌려 만든다 → 사람이 보는 것과 AI가 보는 것이 같다.

- 개발 빌드 전용 측정 패널을 앱 안에 둔다.

## 11. 기술 스택 (자세한 내용·버전은 `docs/spec.md`)
- **Electron**(확정) · React · Vite · TypeScript — Node로 git 실행·파일 감시·MCP 서버를 한 프로세스에서 다루기 쉬움. cl-app과 같은 조합.
- MCP: `@modelcontextprotocol/sdk` (stdio + localhost 중계)
- 파일 감시: @parcel/watcher · 스키마 검증: zod (스키마에서 JSON Schema를 뽑아 MCP 도구 정의에도 씀)
- Git: 설치된 git CLI를 자식 프로세스로 실행(라이브러리로 git을 다시 구현하지 않음)
- 토큰: W3C Design Tokens(DTCG) 형식, 변환은 Style Dictionary 검토
- 상태: zustand · 되돌리기: 명령 패턴(노드 id 단위 patch)
- 렌더: DOM + CSS(1차), CanvasKit(대안)
- 서체: 앱 UI는 무료 서체(Pretendard·JetBrains Mono 후보)

## 12. 보안
- MCP 서버는 stdio로만 연다. 앱 중계는 TCP 포트 대신 나만 접근할 수 있는 유닉스 소켓(권한 0600)을 쓴다(`docs/spec.md` §4).
- 앱·MCP의 **쓰기는 `freegma/` 안으로 제한**한다. 저장소의 나머지(서비스 코드)는 스펙 감지·토큰 비교·가져오기 분석을 위해 **읽기만** 한다. 예외는 배포 제외 설정(§2-1-2) 하나이고, 사람이 diff를 보고 승인한 줄만 쓴다. git 명령은 저장소 루트에서 실행하되 커밋 경로는 `freegma/`로 한정한다.
- 앱이 Claude Code를 실행할 때(✦ AI 탭, 저장소에서 가져오기)는 `--allowedTools`를 읽기 도구(Read·Glob·Grep)와 freegma MCP로 제한한다. 서비스 코드 수정·셸 실행은 허용하지 않는다. 앱은 Claude 인증 정보를 다루지 않는다(사용자의 Claude Code 로그인을 그대로 씀).
- 렌더러는 `contextIsolation`·`sandbox` 켜고, preload의 좁은 API로만 노드 접근. preload에 «임의 경로 읽기·쓰기» 같은 범용 API를 두지 않는다.
- 디자인 파일 안 텍스트·이미지·링크는 신뢰하지 않는다: 텍스트는 HTML로 해석하지 않고, 프로토타입의 외부 링크는 http/https만 기본 브라우저로 연다.
- 원격 페이지·원격 서체를 불러오지 않는다(서체는 로컬 또는 프로젝트 `assets/`).
- 앱은 인증 정보(토큰·비밀번호)를 받거나 저장하지 않는다(§5-3).

## 13. 나중을 위한 자리
- [푸시] 버튼, 앱 안 병합·pull·브랜치 삭제, 커밋 기록 보기, 두 커밋 사이 디자인 시각 비교(diff 화면).
- JSON 구조 인식 병합 드라이버.
- 컴포넌트 변형(variant) 속성 편집 UI, 스마트 애니메이트.
- 다른 툴에서 가져오기(SVG·이미지 우선, 외부 툴 파일은 검토).
- 스펙 어댑터 추가(vue·swiftui·flutter), 사용자 정의 어댑터.
- 저장소에서 컴포넌트·화면을 읽어 디자인으로 만드는 역방향(코드 → 디자인, §2-7).
- 한 화면(라우트)에 크기별 프레임 묶기(반응형 브레이크포인트), [✦ 코드에 반영]을 여러 화면 한꺼번에.

## 14. 1차 구현 순서
1. 뼈대: Electron + React, 시작 화면(폴더 열기·새 프로젝트·최근 목록·git 확인), 프로젝트 만들기(플랫폼·개발 스펙 선택, 저장소 감지), 파일 형식 읽기·쓰기(안정된 출력), 포맷 버전.
2. 캔버스: 프레임·사각형·텍스트·이미지, 선택·이동·크기, 오토 레이아웃, 레이어 트리, 속성 패널, 되돌리기, 자동 저장 → §10-1·2 확인.
3. 디자인 시스템·토큰·컴포넌트: 프로젝트 만들 때 시스템 생성(템플릿·브랜드 색 단계), DTCG 토큰 편집·연결, 컴포넌트·인스턴스, 디자인 시스템 화면, 시스템 검사 규칙.
4. MCP: `freegma-mcp` headless → 앱 중계, §6 도구(`get_design_system`·시스템 검사 포함), 선택 공유, `render_image`, `DESIGN_SYSTEM.md` 생성 → §10-3·4·9 확인. 이어서 ✦ AI 채팅 탭(Claude Code 세션 실행, 답변 단위 되돌리기) → §10-10 확인.
5. Git: 헤더 변경 수, ChangeDiffer(노드 단위 비교), [커밋] 버튼·커밋 창·메시지 자동 작성, 작성자 설정, 바깥 변경·충돌 처리 → §10-5·6 확인.
6. 개발자 모드: IR + 웹 어댑터(React+Tailwind) → 모바일 어댑터(§16-4), 컴포넌트 연결, 토큰 내보내기 → §10-7·8 확인.
7. 프로토타입: 화면 연결·전환, 미리보기 창.
8. 측정 패널 → §9 목표 확인.
