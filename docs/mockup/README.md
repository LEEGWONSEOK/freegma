# freegma 목업

> 작성: 2026-11-19 · 디자인 시스템 추가 2026-11-21 | 근거: `docs/design.md` §2 화면 구성, `docs/design-system.md`
> 생김새와 흐름을 확인하는 용도. 실제로 그리기·저장·커밋은 하지 않는다.

## 여는 법
`index.html`을 브라우저로 연다(외부 연결 없음, 파일 하나).

```
open docs/mockup/index.html
```

## 맨 위 «목업 탐색 막대» (실제 앱에는 없음)
| 버튼·토글 | 하는 일 |
|---|---|
| 시작 화면 | 최근 프로젝트, 폴더 열기(git 아님 경고 → git init → freegma/ 만들기) |
| 프로젝트 만들기 | 웹/모바일 앱 선택 → 개발 스펙 목록·기본값 표가 바뀜. **디자인 시스템** 칸: 시작 방식 2개. «기본 템플릿»이면 브랜드 색(→ brand 단계 미리보기)·서체, «저장소에서 가져오기 ✦»면 Claude 연결 상태·분석 범위. [만들기] → **배포 제외 설정**(해당 파일 목록·바뀔 내용·적용/건너뛰기) → (가져오기면) Claude 분석 진행 → **가져오기 초안**(출처·확신도·버리기·서체 직접 선택·다시 요청) → 디자인 시스템 화면 |
| 편집 · 웹 / 편집 · 모바일 앱 | 예시 프로젝트(my-shop / my-shop-app) 편집 화면 |
| 디자인 시스템 | 편집 화면의 디자인 시스템 화면을 바로 열기 |
| 커밋 창 | 커밋 창 바로 열기 |
| 충돌 | 헤더 [커밋]이 «충돌 해결 필요»로 바뀌고, 누르면 충돌 해결 창 |
| 작성자 미설정 | 커밋 창에 이름·이메일 입력칸 |
| 훅 실패 | 커밋하면 pre-commit 실패 출력이 커밋 창에 남음 |
| 코드 변경 있음 | 서비스 코드에 커밋 안 된 변경이 있는 상태 — 브랜치 전환이 막히고 이유가 보임 |
| Claude 미연결 | 상태줄이 «AI 연결 안 됨», ✦ AI 탭은 연결 안내만, 프로젝트 만들기의 «저장소에서 가져오기»와 시스템 화면의 [저장소에서 다시 만들기]가 꺼짐 |
| 테마 | 시스템 / 라이트 / 다크 |

## 편집 화면에서 해 볼 것
- **디자인 모드**: 캔버스나 레이어를 눌러 선택 → 오른쪽 속성(토큰 연결은 보라색 칩). 버튼 인스턴스는 label·variant를 바꾸면 캔버스와 헤더 변경 수가 바뀜.
- **이동·확대**: 두 손가락 스크롤 = 이동, ⌃/⌘ + 휠(핀치) = 확대, Space + 끌기 = 이동, 상태줄 [맞춤].
- **프로토타입 모드**: 보라색 연결선, 연결된 레이어 선택 시 인터랙션 내용, [▶ 미리보기] → 웹은 브라우저 틀, 모바일은 기기 틀. 누를 곳을 모르면 아무 곳이나 누르면 표시됨.
- **개발 모드**: 레이어 선택 → 스펙에 맞는 코드(웹 = React + Tailwind, 모바일 = React Native), 쓰인 토큰, 연결된 컴포넌트, 패딩 표시. 아무것도 선택하지 않으면 토큰 내보내기 미리보기.
- **상태줄**: «AI 연결됨» → MCP 등록 명령, «선택 공유», «✦ 방금 AI가 2개 수정» → 해당 레이어 강조.
- **커밋**: 헤더 [커밋] → 변경 목록(누르면 해당 화면으로 이동) + 자동 작성 메시지 → 커밋 → «커밋됨 · 해시» 알림, 변경 수 0.
- **왼쪽 탭**: 레이어 / 컴포넌트(코드 연결 경로 표시) / 토큰. 맨 위 «◆ 디자인 시스템에서 보기·고치기»로 시스템 화면 이동.

## 새 화면 → 코드 반영 해 볼 것 (design.md §2-7)
- 왼쪽 **화면 목록**: 도메인(홈·상품·주문 …)별로 묶여 있고, 도메인을 누르면 캔버스에 그 도메인 화면만, **▦ 전체 보기**는 전부(프로토타입 모드의 «흐름 보기»). 화면을 누르면 그 화면으로 확대.
- **[+ 화면]** → 역할(화면/시안)·이름·크기·라우트·도메인(라우트에서 자동 제안, 새 이름을 쓰면 새 도메인) 입력. 라우터 규칙으로 코드 파일이 제안됨(웹: React Router `src/pages/…Page.tsx` + `src/router.tsx` 등록, 모바일: Expo Router `app/….tsx`).
- 캔버스 프레임 이름·레이어 트리에 코드 상태: ○ 코드 없음 · ◐ 디자인이 더 새로움 · ✓ 코드 최신. 디자인 모드 오른쪽 «화면 · 코드»에서 역할·도메인 바꾸기, **[＋ 시안 만들기]**(화면을 복제해 원본 옆에 붙임, 코드로 안 감).
- 개발 모드: 아무것도 안 고르면 **화면 목록**, 화면을 고르면 **[✦ 코드에 반영…]** → 반영 꾸러미(파일·라우트·바뀐 것·컴포넌트·토큰·화면 이동, `get_handoff` 원문) → [✦ 터미널에서 Claude로 반영] → 잠시 뒤 «코드 커밋 감지 · Design-Ref» → ✓.
- ✓ 화면을 디자인에서 고치면 ◐로 바뀌고 «바뀐 것»에 쌓임.

## 브랜치 메뉴에서 해 볼 것 (design.md §2-2-1)
- 헤더 **⎇ main ▾** 누르기 → 브랜치 목록. 처음엔 freegma 변경 4개가 있어 **전환이 막히고** 이유가 보임.
- **+ 새 브랜치 만들기…** → 이름(`design/product-detail-…`) 입력 후 Enter: 파일·변경 수 그대로 새 브랜치로.
- [커밋]으로 변경을 비운 뒤 다시 열면 전환 가능 → 확인 창(«서비스 코드도 함께 바뀝니다») → 전환. AI 대화는 브랜치마다 따로.
- 탐색 막대 «코드 변경 있음»을 켜면 freegma 변경이 없어도 전환이 막힘.

## ✦ AI 탭에서 해 볼 것 (design.md §2-6)
- 오른쪽 위 **[속성 | ✦ AI]** 탭 또는 **⌘L**. 선택한 레이어(또는 시스템 항목·도메인)가 입력창 위 «대상» 칩으로 붙음.
- 정보 카드 선택 → «간격 좀 더 넓혀줘»: spacing 단계 안에서만 바꾸고, 캔버스에 청록 강조, «✦ 1개 수정 · [보기] [이 답변 되돌리기]».
- 찜 버튼 선택 → «이 버튼을 primary로 바꿔줘»: 화면에 이미 primary가 있어 **규칙 때문에 바꾸지 않고 이유를 답함**.
- 아무것도 선택 안 함 → «이 화면에 primary 버튼이 몇 개야?»: 읽기만 하고 답함(수정 없음).
- 디자인 시스템 화면 → «primary 색을 조금 더 진하게»: «◆ 디자인 시스템 변경 — 모든 화면에 영향» 표시, 커밋 창에 시스템 변경으로 나옴.
- «Claude 미연결»을 켜면 AI 탭은 연결 안내만 보임.
- 목업 한계: 정해진 몇 가지 요청만 흉내 냄(실제 앱은 사용자 PC의 Claude Code가 MCP 도구로 처리).

## 디자인 시스템 화면에서 해 볼 것
- **들어가기**: 왼쪽 맨 위 «디자인 시스템 › ◆ ○○ 시스템». 왼쪽 아래가 시스템 목차(기초 / 기본 컴포넌트 / 서비스 컴포넌트 / 규칙)로 바뀜.
- **개요**(아무것도 안 고름): 오른쪽에서 **브랜드 대표 색**을 바꾸면 brand.50~900 → color.primary → 모든 화면이 함께 바뀜. 서체, AI 원시값 처리(경고 후 반영 / 거절), **[✦ 저장소에서 다시 만들기]**(Claude 분석 → 초안 → 확정하면 커밋 창에 변경으로 나옴).
- **색**: 기초값(직접 쓰지 않음)과 의미 토큰 두 층. 의미 토큰을 누르면 참조할 기초값·용도·피할 곳을 고치고, 사용처(레이어) 목록·저장될 DTCG JSON이 보임. 사용처를 누르면 그 화면·레이어로 이동.
- **글자·간격·모서리·그림자**: 글자 스타일 5개(크기 토큰·굵기·줄 높이), 간격 단계 값 바꾸기.
- **컴포넌트**: 기본(Button · Input · Badge · Card)과 서비스(NavBar · ProductCard · CartItem). 변형 × 상태 견본, 쓸 때 / 피할 때 / 접근성 편집.
- **✦ AI가 읽는 형태 보기**: MCP `get_design_system` 응답과, AI가 `#3B82F6`·`gap: 14`를 보냈을 때의 응답(경고 / 거절).
- **커밋**: 시스템을 고치면 헤더 변경 수가 늘고, 커밋 창에 «디자인 시스템» 묶음 · 범위 `design(system)`. 항목을 누르면 시스템 화면의 그 항목으로 이동.
- 개발 모드로 바꾸면 오른쪽이 토큰 내보내기 미리보기.
- 목업 한계: 웹·모바일이 같은 토큰 값을 쓰고(실제로는 플랫폼별 글자 단계), Claude 분석·초안은 정해진 예시 결과(브랜드 색 #4F46E5)이며 컴포넌트 변형은 템플릿 그대로 보임. 배포 제외 설정은 파일을 실제로 쓰지 않음.

## 목업에서 정할 것 (피드백 받을 항목)
1. 패널 배치·폭(왼쪽 248, 오른쪽 속성 340 · ✦ AI 400 · 개발 모드 420 — 경계를 끌어 280~640 조절, 두 번 누르면 기본값, 탭별로 기억)
2. 헤더 구성(브랜치·변경 수·[커밋] 위치), 브랜치 메뉴의 전환 막힘 안내 문구
3. 강조색(보라) · AI 표시색(청록)
4. 개발 모드 코드 패널의 정보 순서
5. 커밋 창 구성·메시지 형식
6. 디자인 시스템: 왼쪽 네비 위치, 문서 화면의 절 순서, 기본 컴포넌트 4종이 적당한지, AI 원시값 처리 기본값(경고 후 반영)
7. 프로젝트 만들기 흐름: 배포 제외 설정 단계의 항목·문구, 가져오기 초안 표의 열(출처·확신도)과 버튼
8. ✦ AI 탭: 오른쪽 탭 위치, 대상 칩·제안·도구 표시의 정보량, 답변 되돌리기 버튼
9. 화면↔코드: 도메인별 화면 목록·전체 보기, [+ 화면] 창의 칸, 시안 붙이기, 코드 상태 기호(○◐✓), 반영 꾸러미 창의 정보 순서

정해진 값은 개발 착수 때 앱 UI 토큰(`index.html` 맨 위 `:root` 변수)으로 옮긴다.
